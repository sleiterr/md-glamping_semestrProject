# Components Guide

This document describes the key React components used throughout the Gittes Glamping frontend.

## 📐 Component Architecture

Components are organized by functionality:
- **Layout Components**: Header, Footer, OverlayHeader
- **Page Components**: Home, LoginPage, Backoffice, etc.
- **UI Components**: Button, Input, Form elements
- **Feature Components**: StayList, ActivitiesList, Login, ProtectedRoute

## 🔐 Authentication Components

### LoginForm
**Location**: `src/components/Login/LoginForm.jsx`

Handles user login with email and password validation.

**Features**:
- Formik form with Yup validation
- Email and password validation
- JWT token handling via `jwtDecode`
- Role-based navigation (admin → /backoffice, guest → /my-list)
- Error toast notifications

**Usage**:
```jsx
<LoginForm onLogin={handleLogin} />
```

### ProtectedRoute
**Location**: `src/components/ProtectedRoute/ProtectedRoute.jsx`

Guards routes that require authentication and specific roles.

**Features**:
- Checks for valid JWT token in localStorage
- Validates token expiration
- Role-based access control (admin/guest)
- Redirects to login if unauthorized

**Usage**:
```jsx
<Route
  path="/my-list"
  element={
    <ProtectedRoute allowedRoles={["admin", "guest"]}>
      <MyList />
    </ProtectedRoute>
  }
/>
```

**Location**: `src/components/Login/Input.jsx`

Form input with validation error display.

**Props**:

- `placeholder`: Placeholder text

- `error`: Error message

## 🔄 State Management

### App-level State
**Location**: `src/App.jsx`

Uses `useLocalStorage` from `@uidotdev/usehooks` for:
- **token**: JWT authentication token
- **favorites**: User's favorite accommodations

### Component State
- Form state managed with **Formik**
- Component state with **useState**
- Side effects with **useEffect**

## 📱 Responsive Design

All components use:
- **Tailwind CSS** for responsive utilities
- Mobile-first design approach
- Breakpoints: sm, md, lg, xl
- Flexible layouts with flexbox/grid

## 🎨 Styling Approach

- **Tailwind CSS**: Primary styling utility
- **Styled Components**: For dynamic/complex styling
- **Custom CSS**: In component style files (when needed)
- **CSS Modules**: Optional for component-scoped styles
